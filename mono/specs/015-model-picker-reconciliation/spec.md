# 015 · 模型选择弹窗的 DOM 更新收敛

## 问题

多个连接的 host 会各自运行 Mono client bundle，但 DOM 适配器作用于同一个 document。006 的 provider 数量改写使用 `textContent`；隐藏模型配置不同的两个实例会交替改写同一个数量节点。两个全局 MutationObserver 经 `queueMicrotask` 互相唤醒，微任务队列无法清空，模型弹窗与整个界面停止响应。

## 目标

- 多个 Mono 实例同时运行且隐藏模型配置不同时，打开 draft agent 模型选择仍可交互。
- 保留模型隐藏、可见模型数量、Provider 模型开关以及原有布局调整。
- 保留宿主数量文字节点，卸载后恢复宿主显示；宿主更新总数后仍重新计算。
- DOM 更新按帧合并，卸载时取消待执行的帧。

## 非目标

- 新增宿主 API 或修改 Paseo 源码。
- 改变多个 host 模型隐藏 CSS 叠加的现有行为；此规格修复其 DOM 更新反馈循环。

## 验收

- 实际适配器在 Chromium 中运行两个独立实例：隐藏 4 个 / 不隐藏，原实现达到微任务限额，修复后更新收敛。
- 宿主总数变化、模型重新显示、卸载清理、取消已排队帧均通过回归验证。
- `npm run typecheck`、`npm test` 通过，重载 `mono` 后状态正常。
