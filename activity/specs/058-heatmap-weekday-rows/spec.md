# 058 — 热力图回到 weekday 行 / 自然周列（Codex 样式）

- 状态：已实现，页面验收待完成
- 日期：2026-09-21
- 依赖：002（热力图）、021（固定 52 列）
- 修订：048「364 天连续矩形、今天固定右下角」以本目录为准

## 1. 背景

048 把热力图改成「今天往前数 363 天」的连续矩形：每列 7 天但不对齐星期，
行不再有 weekday 含义。代价是同一行里的格子横向对比没有语义——第 3 行可能是周三，
也可能是周五，读者无法像 GitHub / Codex 的贡献图那样「按行看某个星期几」。

参考 Codex 的 Token activity：7 行 = weekday（第一行周日 … 最后一行周六），
每列 = 一个完整自然周。

## 2. 目标

| ID | 目标 |
|---|---|
| G1 | 行索引 === weekday，第 0 行周日、第 6 行周六 |
| G2 | 每列是一个周日起的自然周；最后一列是今天所在的那一周 |
| G3 | 仍固定 52 列 × 7 行；首列完整（周日开头），窗口共 364 个日期 |
| G4 | 最后一列中今天之后的日期为 `future`，不渲染（右上角留白，同 GitHub / Codex） |
| G5 | Weekly 列起点与自然周起点重合；Daily / Cumulative 口径不变 |

## 3. 非目标

- 不改 range chips 的过滤语义（021：只过滤数据，不改布局）
- 不改月份轴（仍 12 个均匀标签，末月 = 今天所在月）
- 不加 weekday 行标签（Codex 参考图也没有）
- 不改配色、tooltip 文案、cell 尺寸自适应

## 4. 行为

- `start = startOfWeekSunday(today) - 51 周`，`end = today`
- 列循环步长 7 天，共 52 列；每列 7 个格子，行 i 的 `getDay() === i`
- `future = date > today`：客户端已有 `opacity: 0` 分支，无需改动
- `excluded` 恒为 false（首列即窗口起点）
- Cumulative 仍带入窗口前的历史；未来格子无数据，不影响累计
- 可见日期数 = 364 −（6 − today.getDay()）：周六时满 364，周日时 358

## 5. 取舍

048 想避免的「末列只有一天」在本方案里会出现（今天是周日时最后一列只亮 1 格）。
这是 weekday 对齐的固有代价，GitHub / Codex 同样如此，换来的是行的语义可读性。
