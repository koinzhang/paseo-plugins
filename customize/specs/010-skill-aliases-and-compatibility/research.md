# Research

- OpenCode official [skills documentation](https://opencode.ai/docs/skills) lists `.opencode`, `.claude`, and `.agents` project and global skill roots, and says skills are loaded on demand through the `skill` tool. Same-name definitions should be unique across locations.
- OpenCode source and its own [customization guidance](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/plugin/skill/customize-opencode.md) include `OPENCODE_DISABLE_EXTERNAL_SKILLS` and `OPENCODE_DISABLE_CLAUDE_CODE_SKILLS`. The installed local OpenCode version examined was 1.18.32. These are process environment flags, not an `opencode.json` switch.
- Cursor's installed agent bundle (2026.09.23) defaults `thirdPartyExtensibilityEnabled` to true when no option is passed and resolves `realSkillMdPath` for duplicate skill roots. The Cursor IDE stores `cursor/thirdPartyExtensibilityEnabled` in `User/globalStorage/state.vscdb` (macOS path under `~/Library/Application Support/Cursor`). The IDE setting can differ from an independently started CLI agent.
- Current Customize `EntrySink` deduplicates only the lexical path, so a symlinked root produces several rows for one physical file. Existing Cursor and OpenCode mechanism copy is static.
- The OpenCode skill loader uses recursive `skills/**/SKILL.md` discovery; Customize previously scanned only one level, so this change aligns its scan depth with the loader.
- The installed OpenCode version is 1.18.32. Its [V1 skills documentation](https://opencode.ai/docs/skills) describes automatic advertisement in the `skill` tool and on-demand loading of the body. It documents `permission.skill` allow/ask/deny, but no per-skill manual-only discovery field. The [feature request to honor `disable-model-invocation`](https://github.com/anomalyco/opencode/issues/34498) remains open; V2's `opencode/autoinvoke` documentation applies to a different version line.
